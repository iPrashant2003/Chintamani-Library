SCHEDULE A

Detailed Feature and Technical Specification of the Software Ecosystem

Module / Component Technical Architecture & Functional Specification
Part 1: Mobile App
(Cross-Platform)
  • Framework: Flutter / Dart compiled into native Android release build.
  • OTA Updater Engine: Background lifecycle resume observer & in-app auto-updater; checks cloud releases on startup and resume.
  • User Interface: 4D Claymorphic luxury tactile design with gold glowing accents, custom cards and animated press states.
  • Authentication: Biometric fingerprint/face auth + secure fallback PIN.
  • Offline Support: Hive & SQLite offline caching ensuring dashboard accessibility during network dropouts.
  • Attribution: Permanent 'Developed by Prashant Mani Tripathi' gold badge in Splash, Drawer, and About screens.
Part 2: Web Portal
(Universal QR)
  • Technology: HTML5, Tailwind CSS, JavaScript mobile-first responsive architecture.
  • Self-Admission: Direct student registration via branch QR scan.
  • Photo Upload: Device storage/gallery picker with strict 5MB file size validation and zero-copy multipart upload to Cloudinary (zero low-memory errors).
  • Attendance Engine: Instant QR check-in / check-out with branch timestamps.
  • Branch Switcher: Sliding branch switcher for Khalilabad and Mehdawal.
Part 3: Cloud Backend & Database
  • API Server: NestJS / TypeScript REST services deployed on Render.com cloud infrastructure.
  • Database: Neon PostgreSQL serverless relational database with automated daily backups.
  • Media Storage: Cloudinary CDN with branch-isolated folder paths (chintamani/mehdawal/ and chintamani/khalilabad/).
  • Security: HTTPS SSL in transit, secret management via Render environment variables, role-based guard middleware.
Part 4: Dual-Branch Data Isolation
  • Branches at Go-Live: Khalilabad Branch (72 Seats) and Mehdawal Branch (65 Seats).
  • Isolation Architecture: Complete logical segregation of members, admissions, attendance, fees, seat matrix, and complaints per branch. Zero cross-branch data bleeding.
  • Future Branch Support: Modular multi-branch database schema allowing seamless addition of new branches under Clause 5.6.
Part 5: Out of Scope
(Requires Separate SOW)
  • Native iOS App Store packaging (requires Apple Developer Program enrollment by Client).
  • External biometric hardware terminal integrations (fingerprint scanner turnstiles).
  • Multi-state white-label franchise multi-tenancy software redesign.
  • Custom accounting software / Tally integrations beyond standard CSV exports.
